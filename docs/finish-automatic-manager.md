# Guarded manager implementation

The seasonal manager implementation connects source-bound Yahoo observations, a persistent manager identity, validated decisions, guarded execution and independently evidenced outcomes. Merging this code does not activate production or promote the seasonal release.

## Review map

- [Owned sources](owned-sources.md): complete, fresh roster/rules/player evidence; unknown evidence blocks execution.
- [Acquisition collection](owned-acquisition-collection.md): explicitly bounded candidate pages and known pending claims.
- [Manager transport](openclaw-manager-transport.md): same registered actor, exact terminal result and verified session rollover.
- [Participant outcomes](participant-outcomes.md): proposals precede execution; independent readback determines action credit.
- [Lineup release](owned-lineup-operational-release.md): one atomic two-player swap per occurrence.
- [Acquisition release](owned-acquisition-operational-release.md): one acquisition per occurrence with separate waiver and pickup proofs.

## Activation boundary

Operational hosts require reviewed source/SHA pins, original private sandbox evidence, matching team/profile scope, a fresh decision, a bounded action window and two independent enabled write gates. Unknown outcomes remain unresolved in the ledger and are never blindly resubmitted. A pending waiver is not a completed roster acquisition.

The implementation retains exact local repository, team and browser-profile pins. It is not a portable generic deployment. Private runtime configuration, original captures, participant memory, scheduler state and acceptance receipts are deliberately not distributed. Test fixtures are regression inputs, not operational proof.

Activation, scheduler ownership and operational readback remain separate work. No scheduler, account, production roster or release configuration is changed by this PR.
